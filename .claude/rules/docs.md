# Документация для агентов: как писать и как читать

> Подгружается, когда агент правит документы. Короткая версия — в
> [CLAUDE.md](../../CLAUDE.md), раздел «Как работать, не сжигая контекст».

## Зачем это правило (2026-10-21)

Проект ведут агенты, и каждый начинает с нуля: всё, что не записано коротко и
в предсказуемом месте, он заново добывает чтением кода. До этого правила
`CLAUDE.md` весил ~99 тыс. символов и грузился в каждую сессию и в каждого
субагента ещё до первого действия; `docs/README.md` — 209 КБ, из них 200 КБ
реестр «Что осталось открытым», который правило №26 велит дописывать (то
есть читать). Карты кода не было вовсе: «где живёт X» каждый раз решалось
поиском по ~4 300 файлам.

Принцип тот же, что у всех правил проекта: правило без механизма не работает.
Механизм — гейт `scripts/check-agent-docs.mjs` (CI, джоба `checks`), ниже.

## Где что живёт (один факт — одно место)

| Что | Куда | Грузится |
|---|---|---|
| Правило: одна строка | `CLAUDE.md` | всегда |
| Правило: полный текст, инцидент, обоснование | `.claude/rules/<тема>.md` с `paths:` | сам, по маске файла |
| Где что лежит в коде, куда идти по задаче, таблица гейтов | `docs/ARCHITECTURE.md` | по ссылке, первым делом |
| Неочевидное про один модуль | шапка-комментарий его главного файла + строка в карте | при чтении файла |
| Открытое, недоделанное, осознанно не сделанное | `docs/open/<область>.md` (№26) | grep по ключу |
| Инцидент | `docs/INCIDENTS.md` (№20) | grep |
| Идея или задача владельца | `docs/BACKLOG.md` | по задаче |
| Аудит, план, исследование | `docs/<ИМЯ>.md`; закрыт — в `docs/archive/` | по прямой ссылке |
| Env-переменная | `src/infra/env-registry*.ts` + `docs/ENV.md` (№22) | по задаче |
| Промах карты | строка в `docs/agent/NAV_LOG.md` | при настройке карты |

Ссылка, а не копия: второй экземпляр факта разъезжается с первым (правило №4).
Если факт нужен в двух местах, во втором стоит ссылка на первый.

## Как писать

- **Пиши для grep, а не для чтения подряд.** Заголовок — ключ, по которому
  ищут («Счётчик попыток в Postgres», а не «Разное»). Пути и имена — в
  `обратных кавычках`, целиком (`src/infra/cron-leader.service.ts`, а не
  «сервис аренды»). Ссылка на работу — номер PR (`#123`), не «этот PR».
- **Сначала действие, потом история.** Строка правила в `CLAUDE.md` — что
  делать и какой гейт проверит. Инцидент и обоснование — в файле темы.
- **Бюджеты.** `CLAUDE.md` — не больше 200 строк и 16 000 символов
  (гейт); одно правило — одна строка. Файл темы `.claude/rules/*.md` — не больше
  24 000 символов: вырос — раздели тему на две с более узкими `paths`.
  Живой документ в `docs/` больше ~50 КБ — дроби по областям, как `docs/open/`.
- **Маска `paths:` — узкая.** Правило грузится в контекст на каждое чтение
  совпавшего файла; маска `**/*` превращает его в второй `CLAUDE.md`. Файл
  темы без `paths` грузится всегда — такой запрещён гейтом.
- **Для людей — HTML-комментарии.** `<!-- … -->` в `CLAUDE.md` и правилах
  в контекст агента не попадает: пояснения «почему так устроено» для владельца
  пиши туда.
- **Закрытый аудит или план уезжает в `docs/archive/`**, его открытые хвосты —
  строками в `docs/open/`. В `docs/` верхнего уровня остаётся то, по чему
  работают сейчас.

## Как читать

1. `CLAUDE.md` (уже в контексте) → `docs/ARCHITECTURE.md` → нужный модуль →
   код. Правило темы подгрузится само, когда откроешь файл области.
2. Большой файл — `grep -n 'ключ' файл`, затем Read с `offset`/`limit`.
   Целиком не читаются: `docs/AUDIT_*`, `docs/open/*`, `docs/INCIDENTS.md`,
   `docs/RUNBOOKS.md`, `.github/workflows/*.yml`, `scripts/*-baseline.json`,
   `src/articles/articles.seed.ts`. Не читаются вовсе без прямой нужды:
   `schema-miniapp/dist/`, `package-lock.json`, `docs/archive/`.
3. Для широкого поиска — субагент `Explore` (ему не нужен `CLAUDE.md`, он
   возвращает вывод, а не содержимое файлов). Субагенту в ТЗ передай пути из
   карты: «начни с `src/booking/booking.create.ts`» дешевле, чем «найди, где
   создаётся бронь».

## Петля обратной связи: карта чинится промахами

Карта не бывает полной сразу; она дополняется тем, что агенту пришлось искать.

- **Пришлось лезть в код за тем, что должно было быть в карте**, —
  в том же PR допиши строку в `docs/ARCHITECTURE.md` (или в правило темы) и
  строку в `docs/agent/NAV_LOG.md`: что искал, где нашёл, что дописал.
- **Карта соврала** (файл переехал, модуль делает другое) — исправь строку
  карты, промах в журнал с пометкой «устарело».
- **Нашёл сразу** — в журнал ничего не пиши: журнал — про промахи, не про
  успехи, иначе его никто не читает.
- Раз в месяц или перед крупной работой — `/tune-docs`: журнал читается
  целиком, повторяющиеся промахи становятся строками карты или правилами,
  разобранные записи уходят из журнала.

## Механизм принуждения — `scripts/check-agent-docs.mjs`

CI (джоба `checks`) краснеет, если:

- `CLAUDE.md` вышел за бюджет строк или символов (видимых, без HTML-комментариев);
- у файла `.claude/rules/*.md` нет маски `paths:` или он вышел за бюджет;
- относительная ссылка в `CLAUDE.md`, `.claude/**/*.md`, `docs/ARCHITECTURE.md`,
  `docs/README.md`, `docs/open/*.md` ведёт в никуда;
- каталог модуля (`src/*/`, `shared/src/*/`, корневые каталоги фронтендов и
  репозитория) не упомянут в `docs/ARCHITECTURE.md`;
- гейт `scripts/check-*.{mjs,ts}` не упомянут в таблице гейтов карты;
- файл `docs/open/*.md` не упомянут в индексе `docs/README.md`.

Протухшая строка (упомянут каталог или гейт, которого нет) красит так же:
карта, которая врёт, хуже карты, которая молчит.
