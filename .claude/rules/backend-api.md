## 5. Идентичность для rate-limit — только верифицированная
Троттлинг-бакет строится по проверенной подписи (JWT/initData). Всё
неверифицированное бакетируется по IP (или `uid|ip`). Иначе лимит
обходится ротацией фейкового `sub`.

Идентичность бакета — не единственное условие: штатный `@nestjs/throttler`
считает хиты в памяти процесса, а на Amvera обычно больше одного инстанса —
у каждого свой счётчик. Инцидент 2026-09-13: на `POST /api/booking/book`
стоял `@Throttle({ long: { limit: 6, ttl: 3_600_000 } })`, семь запросов за
3 минуты — и ни один не получил 429, потому что запросы разошлись по разным
инстансам. Счётчик денежных/заявочных и кодовых ручек (booking/donation/subscription,
2FA, merge, билеты входа/привязки, заявка терапевта, письма на произвольный адрес)
переехал в Postgres — модель `ThrottleHit`, `HybridThrottleStorage` маршрутизирует
по ключу (`src/api/hybrid-throttle-storage.ts` + `postgres-throttle-storage.ts`):
маршрут, помеченный `@PersistentThrottle()` (`src/api/persistent-throttle.decorator.ts`),
получает `db:`-префикс ключа в `UserThrottlerGuard.generateKey` и считается в
Postgres общим на все инстансы счётчиком; остальные маршруты остаются в
памяти, как раньше (не грузить БД записью на каждый запрос сайта). Атомарность
— один `INSERT … ON CONFLICT DO UPDATE`, доказана на живом Postgres
(`test/throttle-storage.e2e-spec.ts`, правило №18), мок `$queryRaw` её не
проверяет. При недоступной БД — деградация в память на этот один вызов
(`warn`, не `error`: авария БД алертится отдельно).

Механизм принуждения — классификация, не поиск признака: **`scripts/check-persistent-throttle.mjs`**
(CI, джоба `checks`) требует решения о КАЖДОЙ ручке контроллера, у которой есть
`@Throttle(` либо в теле `verifyCode(`/`assertSourceTotp(`/`confirmSetup(`/`regenerateRecoveryCodes(`/`totp.disable(`/`consumeEmailToken(`/`.approve(`/`.deny(`/`.submit(`:
метка (`@PersistentThrottle()`, составной `@PersistentThrottleLimit(...)` из
`src/api/persistent-throttle-limit.ts`, `AdminThrottle()` на классе) либо запись
`exempt` с причиной ≥20 символов и `since` в `scripts/persistent-throttle-baseline.json`.
Протухшая запись (маршрута нет или метка уже стоит) тоже красная. Флага
`--update` нет намеренно. Лимиты кодовых ручек — `src/auth/auth-throttles.ts`.
Инцидент-образец: аудит 2026-10 — 8-символьный код человека (`confirm-login`)
перебирался окнами «20 в час», склеенными рестартами. Живые e2e между спеками
сбрасывают счётчики (`test/e2e-support/throttle-reset.setup.ts`).

## 6. Новый эндпоинт = DTO с class-validator
Inline-интерфейсы в `@Body()` дают только compile-time иллюзию. Рантайм
валидируется декораторами DTO + глобальным `ValidationPipe({ whitelist: true })`.
Строковое поле DTO — с верхней границей (`@MaxLength`/`@Length` или формат): тело
принимается до 256 КБ. Гейт `scripts/check-dto-string-bounds.mjs` (CI, джоба `checks`),
исключения — в `scripts/dto-string-bounds-baseline.json` с причиной.

## 19. Приложение живёт на одном хосте; визитка отдаёт только себя (инциденты 2026-09-08 и 2026-09-16)

Решение владельца: **`schemehappens.ru` — единственный хост приложения**
(сайт, вход, `/app/`, продуктовый API). **`kotlarewski.gr` — визитка практики
для клиентов** и отдаёт только себя: главную, запись на консультацию, статьи,
отзывы, оплату/подписку/донат, юридические страницы и админку. Всё остальное с
алиаса — 301 на `schemehappens.ru` с тем же путём и query.

Механизмы:

- **`src/practice-domain.middleware.ts`** — allow-list поверхности визитки
  (`PRACTICE_PAGES`, `PRACTICE_PAGE_PREFIXES`, `PRACTICE_API_PREFIXES`, статика
  по расширению). Всё не из списка, включая `/app/**` и `/api/auth/**`, — 301
  на канонический хост. Спек проверяет оба исхода на каждое правило и
  **сверяет `PRACTICE_PAGES` с `personalRoutes` в `webapp/src/App.tsx`**
  (правило №4): страница, добавленная в SPA визитки без строки в middleware,
  роняет jest — и наоборот.
- **`src/infra/canonical-host.ts`** — один источник «какие хосты 301-ятся на
  канонический» (legacy, `www.`); `main.ts` и `oauth-host.ts` сверяются с ним,
  а не с копиями списка.
- **`src/auth/oauth-redirect-config.ts`** — при старте адреса возврата всех
  настроенных провайдеров сверяются с каноническим хостом; мисконфиг — `error`
  при старте и строка в блоке «Настройки» отчёта `/stats`.
- **`src/auth/oauth-loop-guard.ts`** — маркер на собственном хопе обрывает
  второй проход даже для неизвестной пары редиректоров.

Что из этого следует для работы:

- **Новый домен или алиас — это запись в `canonical-host.ts` (редиректится)
  либо в `practice-domain.middleware.ts` (что именно отдаёт), плюс тест.**
  Хост, который «просто отдаёт всё», запрещён.
- **Кука, поставленная на шаге 1 и читаемая на шаге 2 (double-submit, PKCE),
  ставится только через `oauth-host.ts`** — он знает про хост колбэка.
  `res.cookie` с такой ролью вне этого модуля — красный флаг ревью.
- **Редирект на хост обязан знать, не редиректится ли тот хост сам.** Пара
  редиректоров, не знающих друг о друге, — петля по построению. Новый хостовый
  редирект сверяется с `isRedirectedHost` и несёт loop guard.
- **Допущение о значении env проверяется при старте, а не подразумевается в
  коде.** `redirect_uri`, `WEBAPP_URL`, домен — не то, что «должно быть», а то,
  что стоит в Amvera. Код, который от этого зависит, обязан значение проверить
  и сообщить (`capability-report.ts`), иначе первым о расхождении узнаёт
  пользователь.
- **Тест на шве ставит `Host` явно.** Запрос с `headers: {}` — запрос
  ниоткуда: такой тест проверяет сверку куки и молчит о том, дойдёт ли она
  (правило №14: «тесты стояли по обе стороны шва, но не на шве»).

Механизм принуждения: спек middleware (оба исхода + сверка с `App.tsx`),
`oauth-redirect-config.spec.ts`, `canonical-host.spec.ts`; вопрос на ревью —
«сколько хостов отвечает на этот маршрут и почему больше одного?».
