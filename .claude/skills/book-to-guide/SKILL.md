# Книга → «Справочник»

Справочник растёт из книг, но книга в него не копируется: текст пишется своими
словами по форме раздела, ссылка ведёт на главу. Порядок всегда один —
полка → карта покрытия → согласование → пачки; шаг не пропускается.

## Где что

- **Книги** — только на Mac владельца: `~/Documents/📚 Книги/Психотерапия — схема-терапия, КПТ/`
  (полная полка схема-терапии — архив `~/Downloads/Схема-терапия.zip`, распаковать туда).
  В git не попадают никогда (авторское право, размер). Облачная сессия книг не
  видит: работа идёт в локальной сессии с этой папкой.
- **Полка** — `shared/src/schemaTherapy/guide/sources.ts` (`GUIDE_SOURCES`):
  метка → авторы и название. Сверка меток в текстах — `sources.test.ts`.
- **Карта покрытия книги** — `docs/guide-sources/<метка>.md`, по файлу на книгу.
- **Тексты** — `shared/src/schemaTherapy/guide/` (`modes/`, `schemas/`,
  `techniques/`, `concerns/` — запросы и расстройства, `practice*.ts`, `address/` —
  адреса разделов); форма раздела — `types.ts`.
- **Структура, связи, чек-листы добавления** — `.claude/rules/knowledge-base.md`;
  сторож — `shared/src/schemaTherapy/kb/`.

## 1. Полка

Книги нет в `GUIDE_SOURCES` — добавь строку: короткая метка (фамилия первого
автора или короткое имя, как «Кембридж»), `author`, `title` с годом. Название и
год — с титульного листа файла (`pdftotext -l 6`), не по памяти; не сверено —
`title` не ставится.

## 2. Карта покрытия

Сначала каталог-цель (`shared/src/schemaTherapy/kb/catalog.ts`, правило `knowledge-base.md`,
раздел 7): какие темы `planned` и `needs_source` эта книга закрывает. Их главы идут в карту
первыми.

Книгу целиком в контекст не читай. Оглавление: `pdftotext -f 1 -l 15 <файл> -`
(epub — `unzip -p <файл> '*.xhtml' | sed 's/<[^>]*>//g'`). Главы разбирает
субагент по одной-две за раз и возвращает строки карты, а не текст книги. Что он обязан
вернуть по каждой главе, кроме приёмов и шагов:

- строку на вводную главы и на каждый абзац «зачем так устроено» (обоснование порядка,
  механизм) — даже если приёма в нём нет;
- на каждый диалог или кейс — «что показывает» одной фразой и реплики терапевта-образцы;
  «кейс — пропустить» ставится только кейсу без приёма и без формулировки;
- на каждую таблицу и рисунок — строку «табл. N: куда» или «есть в <запись>»;
- «пропустить · уже взято» — с записью, полем и словами из записи, по которым это видно:
  совпал только вывод, а шаги, обоснование или формула потеряны — это «дополнить», не «взято».

Шаблон `docs/guide-sources/<метка>.md`:

```markdown
# <Метка> — <авторы>, «<название>», <год>

Файл: `<имя файла в папке книг>`. Статус: карта | согласовано | в работе (PR) | разобрано.

| Глава | О чём (одна строка) | Куда | Решение владельца |
|---|---|---|---|
| гл. 3 | ограниченный репарентинг у избегающих | дополнить `modes/avoidance.ts` → Отстранённый Защитник: `relationship`, `voice` | |
| гл. 5 | работа с образами при травме | новая техника `imagery_trauma` | |
| гл. 9 | история метода | пропустить | |
```

«Куда» — одно из (новая запись или тема — с id строки каталога): дополнить запись (файл, id, поле); новая запись в
существующем разделе (режимы, схемы, техники, «Для терапевта»); запрос
`<id>` (статья `guide/concerns/<id>.ts`); пропустить (с причиной).

### Запросы: после карты проверь, какие темы каталога книга кормит

Когда строки карты собраны, пройди `kb/catalogConcerns.ts` и `docs/guide-sources/README.md`:

1. Для каждого `planned`-запроса собери строки карты о нём — и профильную главу, и абзацы
   внутри глав о режимах и техниках («при кластере С…», «у тревожных клиентов…»). Они идут
   пачкой «запрос: <id>» в таблице пачек; строка книги добавляется в `README.md`.
2. Порог статьи: тему кормят две книги полки или одна профильная глава. Набран — пачка
   пишет статью; не набран — строки ждут в пачке, статья появится со второй книгой.
3. Запрос клиента, которого в каталоге нет: порог набран — добавь строку `planned` сам и
   заведи пачку; не набран — «отложено» с причиной. Владельцу — только спорная тема
   (вне схема-терапии, вне онлайн-практики, `out_of_scope`).
4. Тема `written` — те же строки идут пачкой «запрос: досбор <id>».

Новая техника или заметка «Для терапевта», которой нет в каталоге, — строка каталога и пачка
сразу, без порога. Материал, которому в справочнике нет места (новая вкладка, новый вид
записи), не выбрасывай: «Куда» — «раздел-кандидат <имя>», и строка-предложение в «Идеи»
`docs/BACKLOG.md` (правило `knowledge-base.md`, раздел 7).

## 3. Согласование

Решает агент, мерило — польза практикующему терапевту: колонку «Решение» заполняешь сам
(«да · пачка N», «пропустить · причина») и сразу идёшь в пачки. Владельцу — ссылка на карту
для сведения и вопрос только по спорному (тема вне схема-терапии или онлайн-практики).

## 4. Пачки

- Один PR — три пачки одной книги (меньше — только последний хвост книги или если три не влезают
  в 60 файлов/1500 строк). Одна книга — один открытый PR: следующий открывай после мержа
  предыдущего; досбор — так же. Остальное — карточки-задачи (CLAUDE.md, п. 8).
- Своими словами, без цитат длиннее фразы; ссылка — `[<метка>, гл. N]` в тексте
  и в `sources`. Факт, которого нет в книге, не дописывается.
- Форма — поля `types.ts`; обращение — через `tr`, род нейтральный, термины по
  `docs/TERMINOLOGY.md`, голос — `docs/VOICE.md` (гейты `texts.md` проверят).
- Новая техника или заметка «Для терапевта» обязана иметь поле `group` из
  закрытого списка (`TechniqueGroupId`, `PracticeGroupId` в `types.ts`; порядок и
  подписи — `guideGroups.ts`): ближайшая по смыслу группа. Три записи не ложатся ни в
  одну — заведи новую группу сам (причина — в описании PR). Гейт — `guide/guideGroups.test.ts`.
- Новая техника: id в `techniqueIds.ts`, текст в `techniques/*`, знак —
  `webapp/src/components/art/techniqueSigns.ts`; тесты `guide.test.ts` и
  `sources.test.ts` зелёные.
- Каждая связь из книги — в поле связи (`modeIds`, `techniques`, `schemaIds`), не
  только в текст; закрытая дыра — строка удалена из `kb/gaps.ts`; новая запись —
  чек-лист раздела 5 правила `knowledge-base.md`; новая статья, техника, заметка — строка
  каталога `written` в том же PR (`kb/catalog.test.ts`). Проверка —
  `cd shared && npx vitest run src/schemaTherapy src/mode`.
- Пачка «запрос: <id>» — новая статья по образцу `guide/concerns/depression.ts` (поля —
  `concerns/types.ts`): регистрация в `concerns/all.ts`, строка каталога
  `kb/catalogConcerns.ts` → `written`, новое поле — заголовок в
  `address/addressTitlesConcern.ts`, строка в `docs/guide-sources/README.md`. Связи — только
  существующие id и только сказанное в книге. Тесты: `concerns.test.ts`, `kb/catalog.test.ts`,
  `kb/links.test.ts`, `guide/sources.test.ts`. Статья собирает и то, что по теме уже лежит в
  режимах и техниках (ссылкой-полем), и своё: концептуализация запроса, порядок работы,
  ошибки терапевта.
- После мержа пачки — статус карты и строки «Решение» обновлены в том же PR.

## Адреса разделов: «Про клиента» без правки экранов (#1484)

Каждый раздел статьи имеет адрес `<вид>:<id>/<поле>` (`schema:subjugation/coping.surrender`);
модуль — `shared/src/schemaTherapy/guide/address/`, сторож — `address/address.test.ts`.

1. Новая статья или раздел — только через типы `types.ts`. Адрес выводится сам, руками его
   не пишут; новому полю нужен заголовок в `address/addressTitles.ts` (иначе красный tsc).
2. Переименовал или удалил поле, раздел, статью (в том числе опустошил необязательное поле) —
   строка «старый → новый» в `address/addressRenames.ts` в том же PR: иначе тест красный, а
   отметки клиентов теряются. Новые адреса — в бейслайн командой из сообщения теста.
3. Раздел на экране рисуется только через общий компонент раздела (`GuideSection`, адрес —
   `articleAddress` из `webapp/src/components/therapist/guide/marks/guideMarkModel.ts`): свой
   заголовок «вручную» лишает раздел «Про клиента». Сторож — `guideSectionOnly.test.tsx` рядом
   с листами: в `*Sheet.tsx` нет `<section>`/`<h3>` руками, адрес каждого раздела находит текст.
   Новое поле на листе — `<GuideSection … address={at('поле')}>`.
4. Новая техника или заметка «Для терапевта» — с `group` из закрытого списка (правило №29,
   п. 8); новая группа — когда три записи не ложатся в существующие.
5. Новый смысл отметки (например, «потребность → узел колеса») — строка в
   `address/addressTargets.ts`; без неё отметка ложится в `GuideMark`.
