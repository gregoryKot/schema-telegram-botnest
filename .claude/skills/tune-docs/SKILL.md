# Настройка карты по промахам

Карта (`docs/ARCHITECTURE.md`) и правила (`CLAUDE.md`, `.claude/rules/`)
нужны, чтобы агент не перечитывал код. Где они промолчали, агенты пишут строку
в `docs/agent/NAV_LOG.md`. Этот навык превращает журнал в правки карты.

## 1. Замер (до правок)

```bash
node scripts/check-agent-docs.mjs                      # гейт: бюджеты, ссылки, полнота карты
wc -c CLAUDE.md docs/ARCHITECTURE.md .claude/rules/*.md # сколько стоит каждый файл
find docs -name '*.md' -size +50k -not -path 'docs/archive/*' -exec ls -la {} \;
```

Всегда в контексте — `CLAUDE.md`; остальное грузится по требованию. Растёт
`CLAUDE.md` или файл правила вышел за бюджет — сначала сжать (строка правила
— что делать и чем проверено; история — в файл темы).

## 2. Разбор журнала

Прочитай `docs/agent/NAV_LOG.md` целиком (он короткий по замыслу) и сгруппируй
записи по тому, что искали:

- **Повторяется (2+ раза)** — это дыра карты: строка в `docs/ARCHITECTURE.md`
  в разделе модуля или в «Куда идти по задаче».
- **«Устарело»** — карта врала: проверь соседние строки того же раздела, они
  писались тем же автором в то же время.
- **Нужно было правило, а не адрес** («не знал, что так нельзя») — строка в
  `CLAUDE.md` + полный текст в `.claude/rules/<тема>.md`; спроси владельца,
  если это решение, а не факт.
- **Единичное и узкое** — шапка-комментарий файла, а не карта: карта —
  оглавление, а не справочник.

## 3. Уборка

- Разобранные записи удали из журнала: история остаётся в git, а журнал
  должен читаться за минуту.
- Если правка затронула раздел карты целиком — сверь его с кодом (`Explore`,
  medium) и исправь всё, что не совпало.
- Прогон `node scripts/check-agent-docs.mjs` — зелёный.

## 4. Итог

PR с правками карты и правил; в теле — сколько записей разобрано, какие дыры
закрыты, размеры файлов из замера до и после.
