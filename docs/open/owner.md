**Переезд на VPS** ([MIGRATION_VPS.md](../MIGRATION_VPS.md)):
- **Слово «Amvera» стоит в 14 файлах** (RUNBOOKS ×25, CLAUDE.md ×17, этот README ×12,
  `ci.yml` ×6, SHIELD_PROMPT, prod-smoke.yml, SECURITY, THREAT_MODEL, BOOKING_SETUP,
  ENV и др.), а VPS-ранбука нет: слов «VPS», «dc.sh», «rollback» в RUNBOOKS ни одного.
  DNS уже переключён на `158.160.116.199`, но сервер не отвечает, а `deploy-vps.yml`
  без секретов `DEPLOY_HOST`/`DEPLOY_SSH_KEY`/`PROD_ENV` пропускает девять шагов и
  остаётся **зелёным** — «красная джоба сама сигнал» не работает. Переписывать после
  ответа владельца, кто обслуживает сервер ([AUDIT_2026-10, «Документация и процесс»](../AUDIT_2026-10_FINDINGS.md#документация-и-процесс),
  [«Прод и деплой»](../AUDIT_2026-10_FINDINGS.md#прод-и-деплой)); гейт `check-hosting-name.mjs` — там же.
- **Временная схема «база на VPS, приложение на Amvera»** ([MIGRATION_VPS.md](../MIGRATION_VPS.md),
  раздел «Вариант: только база на VPS»): порт 5432 открыт в интернет, защита —
  пароль (48 hex) и TLS без проверки сертификата (`sslaccept=accept_invalid_certs`);
  `ufw` порты Docker не фильтрует. Мера до переезда приложения на VPS; после него
  `op=transfer-close`. Закрывающий PR убирает эту строку.
- **Образ Caddy не закреплён** (`image: caddy:2` в `deploy/vps/docker-compose.yml`):
  от плавающего тега зависит семантика X-Forwarded-For (v2.5+ не верит XFF клиента и
  пишет адрес пира; число хопов `trust proxy` в `src/infra/trust-proxy.ts` рассчитано
  именно на это). Обновление образа может это изменить; ловит только проба `clientIp`,
  и то после факта. Закрепить версию — вместе с остальными образами compose (Docker
  pinned image, scope F аудита безопасности).
- **Данные после последнего ночного бэкапа при плане Б** (`op=restore-backup`) теряются;
  дозалить их из старой базы, когда она вернётся, можно только вручную по
  `userId` и датам, инструмента нет. Не автоматизировано осознанно: нужен реальный
  дамп старой базы, чтобы проверить сверку, а его пока нет.
- **Логов приложения с VPS в Actions нет намеренно** (репозиторий публичный):
  они лежат на сервере (`docker compose logs`, ротация 5 × 10 МБ). Агенту нужен
  приватный репозиторий с операцией чтения логов, отдельный PR.
- **`DEPLOY_KNOWN_HOSTS` не обязателен.** Без него `ssh-keyscan` берёт отпечаток при
  каждом запуске, и подмену сервера по дороге это не ловит. Принято ради быстрого
  старта; владельцу после первого `bootstrap` положить отпечаток в секрет.

**Видимость в ответах нейросетей** ([GEO.md](../GEO.md), раздел «Открытое»):
- **Главная для робота пуста**: `webapp/index.html` отдаёт `<div id="root"></div>`,
  текст лендинга (услуги, цены, FAQ) есть только в JS и JSON-LD. Статьи и
  список `/articles` уже вкладываются сервером (`src/articles/article-seo.middleware.ts`),
  главная — нет. Сделать по тому же образцу из одного источника с FAQ JSON-LD,
  с тестом-сверкой.
- **Автор описан на двух хостах**: `@id`/`url`/`image`/`sameAs` в JSON-LD
  `webapp/index.html` указывают на `kotlarewski.gr`, `canonical`/`og:url` той же
  страницы — на `schemehappens.ru`, `og:image` — снова `kotlarewski.gr`. Решение
  владельца, где «дом» автора; затем один хост в разметке.
- **Заходы краулеров нейросетей не считаются**: ни счётчика по User-Agent, ни
  блока в `/stats`. Не сделано в #641 осознанно: новая метрика тянет таблицу,
  форматтер и живой спек (правила №8, №18) — отдельный PR.
