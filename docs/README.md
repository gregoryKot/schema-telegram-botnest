## Что осталось открытым

Хвосты закрытых планов — то, что не сделано осознанно, а не забыто:

**Видимость в ответах нейросетей** ([GEO.md](GEO.md), раздел «Открытое»):
- **Главная для робота пуста**: `webapp/index.html` отдаёт `<div id="root"></div>`,
  текст лендинга (услуги, цены, FAQ) есть только в JS и JSON-LD. Статьи и
  список `/articles` уже вкладываются сервером (`src/articles/article-seo.middleware.ts`),
  главная — нет. Сделать по тому же образцу из одного источника с FAQ JSON-LD,
  с тестом-сверкой.
- **Автор описан на двух хостах**: `@id`/`url`/`image`/`sameAs` в JSON-LD
  `webapp/index.html` указывают на `kotlarewski.gr`, `canonical`/`og:url` той же
  страницы — на `schemehappens.ru`, `og:image` — снова `kotlarewski.gr`. Решение
  владельца, где «дом» автора; затем один хост в разметке.
- **Заходы краулеров нейросетей не считаются**: ни счётчика по User-Agent, ни
  блока в `/stats`. Не сделано в этом PR осознанно: новая метрика тянет таблицу,
  форматтер и живой спек (правила №8, №18) — отдельный PR.

**Глобальный аудит 2026-10-11** ([AUDIT_2026-10.md](AUDIT_2026-10.md); находки по
темам — [AUDIT_2026-10_FINDINGS.md](AUDIT_2026-10_FINDINGS.md)). Только P0/P1, которые PR
аудита не чинит:

  заводит владелец: (1) секреты репозитория `BOT_TOKEN` и `ADMIN_ID` — пока их

  [Секция «Прод и деплой»](AUDIT_2026-10_FINDINGS.md#прод-и-деплой).
- **Nightly `mutation-golden-auth` красный с 10-04, issue #614 без владельца**
  (10-12 заведена #642 с той же причиной). `security-log.service.ts` 95.74% →
  65.71%: десять из двенадцати выживших — статические мутанты `ALERT_EVENTS`,

  stryker-конфига. [Секция «Наблюдатели и CI»](AUDIT_2026-10_FINDINGS.md#наблюдатели-и-ci).

  `hardening.invariants.spec.ts` (второй `app.use(helmet(...))` не поймают);
  закрывается общим `configureApp(app)` для `main.ts` и e2e-сборщиков (см.
  «Зеркала e2e-бутстрапа расходятся с `main.ts`» в `AUDIT_2026-10_FINDINGS.md`).
- **Сессия Telegram Web, скорее всего, не получает кросс-сайтовую куку.**
  `isCrossSiteRequest` (`src/auth/auth-http.util.ts:53-58`) читает
  `Sec-Fetch-Site`, а он сравнивает только того, кто начал запрос, с целью и не
  смотрит на предков iframe: `fetch` со страницы `schemehappens.ru/app/` внутри

  refresh-кука выдаётся `Strict` — браузер не пришлёт её из кросс-сайтового
  iframe. К тому же без `Partitioned` (CHIPS) её режет блокировка сторонних кук.
  Не доказано: нужна проверка в настоящем браузере (iframe с родителем на другом
  хосте, логин через `telegram/webapp`, потом `refresh`). Сверка в
  `csrf.invariants.spec.ts` закрепляет соответствие «точка входа — встраиватель»,
