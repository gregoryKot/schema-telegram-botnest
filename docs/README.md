## Что осталось открытым

Хвосты закрытых планов — то, что не сделано осознанно, а не забыто:

**Видимость в ответах нейросетей** ([GEO.md](GEO.md), раздел «Открытое»):
- **Главная для робота пуста**: `webapp/index.html` отдаёт `<div id="root"></div>`,
  текст лендинга (услуги, цены, FAQ) есть только в JS и JSON-LD. Статьи и
  список `/articles` уже вкладываются сервером (`src/articles/article-seo.middleware.ts`),
  главная — нет. Сделать по тому же образцу из одного источника с FAQ JSON-LD,
  с тестом-сверкой.
- **Автор описан на двух хостах**: `@id`/`url`/`image`/`sameAs` в JSON-LD
  `webapp/index.html` указывают на `kotlarewski.gr`, `canonical`/`og:url` той же
  страницы — на `schemehappens.ru`, `og:image` — снова `kotlarewski.gr`. Решение
  владельца, где «дом» автора; затем один хост в разметке.
- **Заходы краулеров нейросетей не считаются**: ни счётчика по User-Agent, ни
  блока в `/stats`. Не сделано в #641 осознанно: новая метрика тянет таблицу,
  форматтер и живой спек (правила №8, №18) — отдельный PR.

**Глобальный аудит 2026-10-11** ([AUDIT_2026-10.md](AUDIT_2026-10.md); находки по
темам — [AUDIT_2026-10_FINDINGS.md](AUDIT_2026-10_FINDINGS.md)). Только P0/P1, которые PR
аудита не чинит:
- **Лежащий прод по-прежнему никому не пишет в Telegram: решение и действия
  владельца.** Код сделан (шаг DM в `alarm` без секретов красный, проба
  `ciRuns` красна на возраст прогона и смотрит только `main`), но каналы
  заводит владелец: (1) секреты репозитория `BOT_TOKEN` и `ADMIN_ID` — пока их
  нет, каждый красный тик смока красит и `alarm`; (2) наблюдатель вне GitHub
  schedule (крон на VPS, аптайм-монитор с DM/SMS): GitHub запускает смок раз
  в 3–7 часов, а проба `ciRuns` и страница техработ (`deploy/front-server.mjs`
  отвечает 200 на любой путь) живут в приложении, которого нет при упавшей
  миграции. Оба инцидента 10-09 и 10-11 записаны в `docs/INCIDENTS.md`.
  [Секция «Наблюдатели и CI»](AUDIT_2026-10_FINDINGS.md#наблюдатели-и-ci).
- **Владельцу: задать `BOT_USERNAME=SchemeHappensBot` в env прода** (Amvera и
  секрет `PROD_ENV` для VPS; без `@`). Дефолта у переменной больше нет
  (`telegram.constants.ts`), и из репозитория не видно, задана ли она сейчас.
  Не задана — после мержа приглашения пар и терапевтов отдают 503, на старте
  `error` в DM, строка в блоке «Переменные» `/stats`, красная проба `telegram`
  (а с ней `/health.selfCheck.failed` и смок прода). `MINIAPP_URL` можно
  удалить (возьмётся `${APP_URL}/app/`) или оставить `https://schemehappens.ru/app/`;
  любой другой хост кросс-проверка `miniappUrlCanonicalHost` покажет в `/stats`.
  [Секция «Прод и деплой»](AUDIT_2026-10_FINDINGS.md#прод-и-деплой).
- **Dev-CORS пропускает старые vercel-хосты** (`src/main.ts:99-100`, только не-прод):
  мусор того же класса, что закрытый дефолт `MINIAPP_URL`. Не смешано с тем PR
  по правилу №20; убрать вместе с проверкой, что dev-мини-апп ходит на свой origin.
- **Деплой на VPS ни разу не выполнялся; `main` не защищён.** `deploy-vps.yml` —
  5 прогонов «success» с пропуском девяти шагов (секретов `DEPLOY_HOST`/
  `DEPLOY_SSH_KEY`/`PROD_ENV` в репозитории нет), `vps.yml` — 0; образ собирает
  автопулл Amvera. Агентская часть «деплой не ждёт CI» закрыта: VPS-деплой
  стартует по `workflow_run` после зелёного CI на push в `main`, гейт
  `deploy-needs-ci.spec.ts` запрещает `push` на воркфлоу с деплоем. Остаток —
  за владельцем: ruleset на `main` (только через PR, required checks = все
  джобы `ci.yml`, **`strict`** или merge queue: во всех четырёх разобранных
  случаях красным стал merge-коммит при зелёном PR, одни required checks этого
  не ловят) и автодеплой Amvera, который о CI не знает и 51 красный push-прогон
  вывез на прод как есть; `branches/main/protection` → 404. Тоже открыто:
  VPS-деплой собирает образ заново, а не берёт его из CI-джобы `docker`
  (`push: false`) — проверен коммит, не байты образа; проба самопроверки,
  сверяющая коммит прода с результатом CI на том же sha, не заведена.
  [Секция «Прод и деплой»](AUDIT_2026-10_FINDINGS.md#прод-и-деплой).
- **VPS-путь не готов к первому настоящему деплою:** автооткат откатывает
  образ, но не `.env` (`cmd_write_env` без `.env.prev`); `pgdata` — единственная
  копия базы между ночными бэкапами R2 (второй слой — в пункте про бэкапы ниже).
  Схему и `release.prev` починили (застрявшая запись миграции снимается при
  откате и в `op=migrate-resolve-failed`, `release.prev` стирается только после
  здорового отката). Осознанно не закрыто: **деструктивная миграция** (DROP/
  RENAME выполнился до падения) — снятие записи огрызок не откатывает, prev-образ
  встанет на новую схему, вернуть её можно только из ночного бэкапа R2
  (`op=restore-backup`, он требует пустую базу и `HOLD_APP`); автоматического
  решения нет, оно упирается в правило «миграции аддитивны и идемпотентны»
  (CLAUDE.md, «Миграции БД», п. 3) и ревью. Смерть приложения по сигналу закрыта
  (entrypoint перезапускает и пишет строку), лимит перезапусков больше не
  паркует навсегда (пауза и новая серия, `deploy/app-exit.mjs`), HEALTHCHECK
  смотрит тело `/health`. Осознанно не сделано: счётчика рестартов и `startedAt`
  в `/health` нет; DM об исчерпанной серии шлёт только приложение при каждом
  своём старте, из entrypoint без приложения сигнала нет (новый канал
  сигнализации, отдельный PR по правилу №20); упавший `migrate deploy`
  по-прежнему паркует без повтора (повтор неидемпотентной миграции задваивает
  DML) и без ограничения по возрасту. Приложение, падающее позже
  `STARTUP_HEALTHY_MS` (60 с) после каждого старта, крутится вечно с паузой 2 с:
  счётчик сбрасывается, лимита нет, DM на каждом круге.
  [Секция «Прод и деплой»](AUDIT_2026-10_FINDINGS.md#прод-и-деплой).
- **Кэш ts-jest в CI не сохраняется: `actions/cache` смотрит не туда, куда пишет jest.**
  `.github/workflows/ci.yml:37` задаёт `JEST_CACHE_DIR: .jest-cache`, и `:53` кэширует
  этот путь от корня репозитория, но jest резолвит относительный `--cacheDirectory`
  от `rootDir` своего конфига (проверено: `npx jest --cacheDirectory=.jest-cache`
  создаёт `src/.jest-cache`, корневого каталога нет; e2e с `test/jest-e2e.json`
  пишет в `test/.jest-cache`). Каждый прогон в CI холодный, шаг «Кэш ts-jest»
  сохраняет пустоту. Чинить: абсолютный путь, `JEST_CACHE_DIR: ${{ github.workspace }}/.jest-cache`;
  после этого устареет комментарий про `src/.jest-cache` в `src/security/collect-source-files.ts:12`.
  Не сделано в PR про `test/.jest-cache`: правило №20, один PR — одна починка.
- **Dependabot: доводка бот-PR (процедура и решения владельца).** Конфиг
  `.github/dependabot.yml` теперь покрывает все пять lock-файлов (сверка —
  `src/test-support/gates/dependabot-coverage.spec.ts`), мажоры идут семейными
  группами (Nest, Stryker, Vitest), `/game` берёт только патчи. Бот-PR красен по
  построению, гейты для него не ослаблены (правило №15). Агент, закончивший свою
  задачу, доводит их вручную, по одной группе:
  (а) **мини-апп** (красный «dist устарел»): в ветке бота
  `npm ci --prefix schema-miniapp && npm run build --prefix schema-miniapp`,
  закоммитить `schema-miniapp/dist`. После пуша бот эту ветку больше не
  ребейзит;
  (б) **webapp** (бандл-храповик): `node scripts/check-bundle-size-ratchet.mjs
  --update` после сборки, в теле коммита назвать, какие пакеты и на сколько КБ
  выросло (правило №15 п.3). Храповик меряет и закоммиченный dist мини-аппа,
  поэтому PR мини-аппа после пересборки тоже может потребовать `--update`;
  (в) **мажоры**: по семейным группам; Nest 12 — отдельная задача, не механика;
  (г) **PR с `@nestjs/throttler` 6.7.1** (ветка бота, #670): после ребейза на
  `main` с этой починкой джоба backend зеленеет (контроль в
  `memory-throttle-reset.spec.ts` не зависит от версии; прод с #677 считает хиты
  в своём `MemoryThrottleStorage`, без таймеров библиотеки).
  **Решает владелец:** (1) включить Dependabot alerts и security updates
  (Settings → Code security): сейчас `dependabot/alerts` отвечает 403
  «disabled», а три high в `game` (postcss, source-map-js под vite) version
  update не чинит; (2) `allow_auto_merge` и required checks на `main`, если нужен
  автомерж групп minor/patch; (3) PAT для воркфлоу, который сам пересобирает
  `schema-miniapp/dist` в ветке бота (пуш через `GITHUB_TOKEN` CI не
  перезапускает); (4) лейблы `dependencies`/`frontend`/`ci`: пока их нет, ключей
  `labels:` в конфиге тоже нет; (5) переезд на Nest 12, Stryker 10, Vitest 5 и
  решение, держать ли мажоры открытыми.
  **После мержа проверить на GitHub:** Insights → Dependency graph → Dependabot
  без ошибок конфигурации, на ближайшем недельном тике появился PR для
  `/shared`. Схему файла офлайн не проверить, тест ловит только структуру.
  Бот закроет текущие PR как superseded и откроет новые: шум на один тик.
  **Сознательно не сделано:** проба самопроверки «бот-PR старше 7 дней» (новая
  внешняя проба, правило №21, отдельный PR); audit-шаги для `shared` и `game` в
  `ci.yml` (`npm audit` смотрит только корень, отдельная находка); одна запись
  `directories:` на три фронтенда (один PR красил бы сразу webapp, мини-апп и
  shared, доводить его тяжелее; vitest-мажор приходит тремя PR с одним именем
  группы, мержить их надо одним заходом, правило №3).
- **30 `scripts/check-*.mjs` (и `feature-parity-patterns.mjs`) обходят дерево через
