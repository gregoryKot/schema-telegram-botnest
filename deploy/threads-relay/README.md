# Ретранслятор Threads

Приложение живёт на российском хостинге, а серверы Meta оттуда не отвечают
даже на попытку установить соединение (`UND_ERR_CONNECT_TIMEOUT` на их IP).
Cloudflare отвечает — поэтому запросы в Threads идут через воркер: приложение
шлёт ему тот же путь, что послало бы в `graph.threads.net`, а он повторяет
запрос со своей стороны.

Через него ходит и публикация, и ночное обновление токена: токен живёт 60 дней
и, если его нечем обновить, канал молча умирает через два месяца.

## Развернуть (10 минут, бесплатно)

1. Заведи аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com) — карта
   не нужна, бесплатного тарифа хватает с большим запасом: у канала две
   публикации в день, лимит — 100 000 запросов в сутки.
2. **Workers & Pages → Create → Start with Hello World → Deploy.** Имя,
   например, `zv-threads`. Получится адрес вида
   `https://zv-threads.<твой-аккаунт>.workers.dev`.
3. **Edit code** → замени всё содержимое на `worker.js` из этой папки →
   **Deploy**.
4. Придумай длинный случайный ключ (это пароль ретранслятора):

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

5. **Settings → Variables and Secrets → Add → Secret**: имя `RELAY_SECRET`,
   значение — ключ из предыдущего шага. Сохрани и задеплой.
6. В переменных Amvera:

   ```
   HEALTHY_ADULT_THREADS_RELAY = https://zv-threads.<твой-аккаунт>.workers.dev
   HEALTHY_ADULT_THREADS_RELAY_SECRET = <тот же ключ>
   ```

   Рестарт — и `/zv threads` должен дойти.

## Если не дошло

`/zv threads` называет, кто именно не ответил: ретранслятор или сама площадка.

- **Не отвечает ретранслятор** — воркер не задеплоен, адрес с опечаткой или
  ключи не совпали (403). Проверь адрес в браузере: воркер обязан ответить
  `forbidden` — значит он жив и просто требует ключ.
- **Ответила площадка** (статус и тело в отчёте) — ретранслятор работает, дело
  в токене или id пользователя.

## Границы

Воркер ходит **только** в `graph.threads.net` — адрес зашит в коде, из запроса
берётся лишь путь и параметры. Без заголовка `x-relay-key` он отвечает 403,
тело запроса никуда не пишет: в параметрах едет `access_token` площадки, и ему
незачем оседать в логах. Токен Threads воркер не хранит — он остаётся в нашей
БД зашифрованным.

Если Cloudflare когда-нибудь перестанет отвечать с российского хостинга, замена
— любой сервер за границей с тем же кодом: приложению всё равно, куда указывает
`HEALTHY_ADULT_THREADS_RELAY`.
